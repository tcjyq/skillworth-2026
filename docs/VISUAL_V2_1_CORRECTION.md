# Visual V2.1 人工复核修正记录

日期：2026-08-22（UTC+8）  
范围：仅 `/lab/visual-v2`；正式首页、数据、算法与 Final 5 均未修改。

## 设计批评

V2 的进步主要来自统一的滚动舞台，但它仍把“持续存在的节点系统”误当成内容主角，造成五个问题：首屏结论被节点稀释；深色低对比降低阅读速度；每个章节使用同一视觉语法而没有高潮；专业指标先于用户语言；硬编码故事节点被误当成产品技能边界。

因此 V2.1 不继续维护 Living Signal Field 为主方向，而转向 **Editorial Evidence Field**：

- 默认界面是高对比浅色数据出版物。
- Hero 是中文编辑式数据封面，5 秒内呈现研究对象、998/313/134/180d、核心结论和继续阅读入口。
- C++ 与岗位转换使用深色沉浸式证据场，成为两个真正的视觉高潮。
- 技能协同、排名稳健性和完整探索回到浅色内容面，优先保证理解和操作。

## 三种明暗策略比较

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 高对比全浅色 | 阅读最轻松、权威感稳定 | C++ 与岗位重排缺少戏剧张力 | 未采用 |
| 浅色内容 + 深色沉浸场 | 编辑可读性与视觉高潮兼得 | 需要严格控制切换次数 | **采用** |
| 重做高对比全暗色 | 延续 V2 识别度 | 仍不符合用户明确的阅读反馈 | 否决 |

## 可视化可读性系统

每个图按以下顺序组织：

1. 中文标题。
2. 一句话结论。
3. 坐标或视觉编码说明。
4. 直接标注重点技能、单位和样本。
5. 用户语言指标。
6. 可展开的进阶指标。

正文桌面端为 16–17px，图表重点标签为 14–20px；移动端不通过压缩字号容纳更多节点，而是减少同屏信息并改为纵向结构。

## Story / Explore 数据边界

- Story Mode：16 个唯一锚点技能，仅用于呈现 Final 5。
- Explore Mode：默认近 180 天返回 134 项技能，其中 110 项进入主排名层，24 项属于已观察技能。
- 搜索基于 API 返回的完整技能名、类型和分类，不再受 Story 节点限制。
- 岗位筛选直接请求该角色的 `eligibility=all` 切片；`skillworth_rank != null` 为主排名层，真实出现但无排名的技能为已观察技能。进入主排名层不等于正式推荐。

## 空图根因

V2 的角色视觉只渲染 Kubernetes、Terraform、Spark、Kafka 四个硬编码锚点，并未读取角色完整技能切片；部分角色自然无法命中这四项，因此看起来为空。另一个容易误判的数据细节是通用技能需求接口会保留目录中的零计数行，必须用 `job_count > 0` 判断真实观察技能。

V2.1 不修改排名算法，而是将主排名层与已观察技能分开。技术产品经理是当前唯一 0 个可排名技能的角色，但仍显示 6 个已观察技能。
